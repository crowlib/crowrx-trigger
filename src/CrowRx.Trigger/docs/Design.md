# 수명과 설계

## 조건과 그룹

`Condition.Initialize()`는 성공한 초기화를 한 번만 수행한다. 초기화 중 예외가 나면 초기화 완료 상태로 바꾸지 않으므로 재시도할 수 있다. `Activate()`는 먼저 활성 상태로 바꾸고 훅을 실행한다. 훅이 실패하면 비활성화를 시도한 뒤 원래 예외를 전달한다. `Deactivate()`는 먼저 비활성 상태로 바꾼다. 그룹은 일부 자식의 비활성화가 실패해도 나머지 자식을 정리한다.

`Condition`은 `IsNot` 값을 보관하지만 만족 결과를 자동으로 반전하지 않는다. 파생 조건이 이를 반영해야 한다. 그룹은 AND·OR 결과에 반전을 반영한다. `IsValid`와 `IsSatisfied`는 별도 조회다. null 목록의 만족값은 true이며, 빈 목록은 AND에서 true, OR에서 false에 반전을 적용한다. 어느 경우든 빈 그룹은 유효하지 않다.

동일한 참조의 조건을 한 트리에 여러 번 넣거나 순환 참조를 만들 수 없다. 서로 다른 인스턴스는 값이 같더라도 허용한다. 중첩 그룹의 null 자식도 허용하지 않는다. 서로 다른 루트 간에 같은 조건을 동시에 사용하는 방식도 피한다.

## 생성과 추가의 차이

| 경로 | 수집과 검증 | 훅·초기화 | 실패 |
|---|---|---|---|
| `ConditionGroup.Create` | 입력 참조를 복사하고 완성된 전체 그래프를 한 번 검증한다. | 추가 훅과 자식 초기화를 실행하지 않는다. 반환 루트는 기본 그룹이다. | 새 그룹을 반환하지 않는다. 열거자의 외부 부수 효과는 되돌리지 않는다. |
| `AddCondition` | 콜백 경계마다 상태와 그래프를 다시 검증한다. | 추가 훅 뒤, 부모가 초기화된 경우 새 자식만 초기화하고 목록에 넣는다. | 후보를 추가하지 않지만 콜백의 외부 부수 효과는 남을 수 있다. |
| `AddConditions` | 입력 순서대로 `AddCondition`을 호출한다. | 각 자식에 기존 추가 계약을 적용한다. | 앞서 성공한 추가는 유지한다. |

`Create`는 최상위 null 입력·원소를 생략하며 자식 인스턴스를 복제하지 않는다. 자식의 기존 초기화·활성화 상태도 바꾸지 않는다. 일반 `IEnumerable`은 한 번만 열거하고 열거자를 해제한다. 배열은 null이 아닌 원소 수를 먼저 세어 목록 용량을 확보한 뒤 복사한다.

`AddConditions`의 배열 분기는 배열 타입의 직접 `foreach` 경로로 인터페이스 열거자 할당을 피한다. 배열을 미리 복사하지 않으므로 추가 훅이 뒤쪽 배열 원소를 바꾸면 바뀐 원소를 읽는다. 일반 열거자의 사용자 코드와 해제 동작도 유지한다. 자신의 `Conditions` 목록을 입력으로 전달하면 순회 중 추가가 발생하므로 사용하지 않는다.

공개 `Conditions`는 가변 List다. 안전한 추가 API를 우회한 변경이나 파생 클래스의 설정 변경은 호출자가 관리한다. 활성화 및 검사 중에는 목록·결합 방식·반전 설정을 바꾸지 않는다. 직접 목록을 수정했을 때도 유효한 트리 구조를 유지해야 한다.

## 검사 세션의 소유권

`CheckAsync` 완료는 그룹 전체의 만족이나 모든 자식의 종료를 뜻하지 않는다. 그룹은 동일 토큰으로 이어지는 호출에서 미완료 자식 작업을 유지하고 이미 완료를 알린 작업만 다시 시작한다. 호출 사이에 새로 완료된 결과는 자식이 만족 상태를 초기화하기 전에 먼저 전달한다. 즉시 완료되는 자식이 있어도 다른 완료 작업의 실패를 함께 확인한다.

토큰이 달라지면 이전 세션을 정리한다. 같은 그룹의 동시 `CheckAsync` 호출은 거부한다. 자식 호출 전후에 목록을 비교해 진행 중인 목록 변경을 감지하며, 시작 중 실패하거나 null Task를 반환하는 자식이 있어도 이미 시작한 검사들을 정리한다.

세션은 조건 스냅샷, Task 목록, 완료 표시 목록, 연결된 취소 토큰을 소유한다. `Task.WhenAny`가 끝났다는 이유로 버퍼를 반환하지 않는다. 모든 시작된 작업과 중첩 그룹의 내부 검사 정리가 끝난 뒤 반환한다. 자식 구현이 취소를 무시하고 끝나지 않으면 그룹과 리스너의 비동기 중지도 끝나지 않는다.

직접 사용한 그룹은 `StopChecksAsync()`로 종료를 기다린다. 활성화하지 않은 검사도 정리할 수 있으며 활성화 상태는 유지한다. 활성화했다면 정리 후 `Deactivate()`를 호출한다. `Deactivate()`만 호출하면 취소는 요청하지만 비동기 정리 완료를 기다리지 않는다. 정리 오류는 `StopChecksAsync()`의 반환 작업으로 전달하며 추가 오류는 로그로 기록할 수 있다.

## 리스너 종료와 재시작

리스너는 시작할 때 조건을 초기화하고 세션에 해당 조건을 보관한다. 성공 후 `IsOneShot`이 false인 경우에만 자동으로 재구독한다. 성공 이벤트의 오류, 유효하지 않은 조건, 검사 오류, 명시적 중지는 자동 재구독 대상이 아니다. 명시적으로 예약한 재시작은 별도로 처리한다.

종료 순서는 취소 요청, 그룹의 잔여 검사 정리, 조건 비활성화, CTS 해제, 현재 세션 상태 해제, 종료 완료 알림이다. 종료 중 `StartListen()`은 한 번의 후속 시작을 예약한다. 다시 `StopListen()`을 호출하면 이 예약도 취소한다. `StopListenAsync()`는 호출 당시 세션만 기다리며 다음 세션을 기다리지 않는다. 정리 오류는 반환 작업을 실패시키는 대신 `Exception` 이벤트로 전달한다.

`Success`는 일반 다중 구독 이벤트다. 한 핸들러가 예외를 던지면 이후 성공 핸들러를 호출하지 않고 오류를 알린다. `Exception`은 핸들러별로 호출하므로 하나의 실패가 다른 오류 핸들러를 막지 않는다. 기본 초기화 훅은 오류 로그 핸들러를 등록한다. 파생 리스너에서 이 동작을 유지하려면 base 훅을 호출한다.

`CheckConditionsImmediately()`는 초기화 후 현재 상태만 동기 확인한다. 만족하면 성공 이벤트를 호출하고, 만족·유효하지 않음·오류에 대해 중지를 요청한다. 비동기 검사나 자동 재구독은 수행하지 않는다. 여러 번 호출하면 만족 상태에서 성공 이벤트도 여러 번 발생할 수 있다.

모든 호출과 상태 변경은 같은 실행 컨텍스트에서 수행한다. `Task.Yield()` 이후 시점은 컨텍스트의 스케줄링에 달려 있으며 한 프레임 대기로 해석하지 않는다. 라이브러리가 Unity PlayerLoop나 메인 스레드 전환을 제공하지는 않는다.

## 대상 공유와 복구

`ConditionGroupShareTarget<TTarget>`은 같은 대상 인터페이스를 구현한 직접 자식에 값을 전달한다. 중첩 공유 그룹은 자신의 전달 로직을 실행한다. 초기화할 때 기존 자식에 전달하고, 나중에 추가되는 자식에는 초기화 전에 전달한다. 일반 그룹이 임의의 대상 전파를 대신 수행하지는 않는다.

대상 변경 전에 상태와 그래프를 검증하고 영향을 받는 대상 값을 스냅샷으로 보관한다. 전달 실패 시 부모와 이미 전달을 시도한 하위 트리를 이전 상태로 복구한다. 부모를 먼저 복구한 뒤 각 자식의 개별 값을 복구한다. 복구도 실패하면 원래 오류와 복구 오류를 AggregateException으로 전달한다. 사용자 setter의 외부 부수 효과까지 되돌릴 수는 없다. 대상 변경 재진입과 대상 변경 중 자식 추가는 허용하지 않는다.

## 최적화 선택과 남은 후보

| 선택 | 이유 |
|---|---|
| 종료 완료 Task 지연 생성 | `StopListenAsync`를 호출하지 않는 실행의 종료 대기용 TCS·Task 할당을 줄인다. |
| 세션과 임시 컬렉션 풀링 | 스냅샷·Task·완료 표시·그래프 검증·대상 복구 버퍼의 반복 할당을 줄인다. 정리 완료까지 세션 소유권을 유지한다. |
| 완료 표시에 `ListPool<bool>` 사용 | ArrayPool과 통합 비교 시 할당량은 같았다. 작은 그룹 자동 재구독 모형과 기존 풀 사용에 맞춰 선택했다. 큰 직접 그룹에는 ArrayPool이 더 나을 수 있다. |
| 별도 `Create` API | 반복 전체 검증으로 인한 대량 추가 비용을 줄이면서 기존 추가 훅·부분 성공 계약을 유지한다. |
| 배열 직접 순회·최종 용량 확보 | 열거자와 목록 성장 중간 배열 할당을 줄인다. 용량 확보에는 원소 수를 세는 추가 순회 비용이 있다. |
| 검사 시작 후 별도 완료 확인 유지 | 순회 통합 후보는 다른 자식 시작 중 앞쪽 작업이 완료되는 경우 불필요한 WhenAny 할당이 늘었다. |
| Task 유지 | UniTask 전환만으로 그래프 검증·세션·CTS 비용은 사라지지 않는다. Unity 통합 요구와 플랫폼 측정 없이 의존성을 다시 추가하지 않는다. |

반복 검증을 구조 버전으로 대체하려면 공개 가변 목록과 중첩 변경 전달 계약부터 설계해야 한다. 세션·CTS의 단순 재사용은 이전 작업의 수명과 취소 콜백 소유권 문제 때문에 적용하지 않았다. 남은 Task·세션 할당은 실제 사용의 병목과 빈도를 확인한 뒤 분석할 후보다. 지금 비교를 마친 채 적용 결정을 기다리는 성능 후보는 없다.

측정 수치, 재실행 명령과 플랫폼 범위는 [검증과 측정](../verification/README.md)에 모았다.
